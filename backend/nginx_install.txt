# Nginx Installation and Configuration Checklist

## Phase 1: HTTP Configuration (Port 80)

### ✅ **Step 1: System Preparation**
- [ ] Update system packages
  ```bash
  sudo apt update && sudo apt upgrade -y
  ```

  ```bash

**Option A: From Ubuntu Repository (Recommended for stability)**
- [ ] Install Nginx from default repository
  ```bash
  sudo apt install nginx -y
  ```

### ✅ **Step 3: Configure Firewall**
- [ ] Check UFW status
  ```bash
  sudo ufw status
  ```
- [ ] Allow SSH (IMPORTANT - do this first!)
  ```bash
  sudo ufw allow ssh

- [ ] Allow HTTP traffic
  ```bash

  sudo ufw allow 80/tcp

- [ ] Verify firewall rules
  ```bash
  sudo ufw status

  ```bash
  sudo systemctl status nginx

### ✅ **Step 5: Configure Your Healthcare API Server Block**
- [ ] Remove Apache2 (if previously installed)
  ```bash
  sudo systemctl stop apache2
  sudo systemctl disable apache2
  sudo apt remove apache2 -y  # Optional
  ```
- [ ] Create directory for your website
  ```bash
  sudo mkdir -p /var/www/healthcare-api
  sudo chown -R $USER:$USER /var/www/healthcare-api
  sudo chmod -R 755 /var/www/healthcare-api
  ```
- [ ] Create server block configuration
  ```bash
  sudo nano /etc/nginx/sites-available/healthcare-api
  ```
- [ ] Add basic HTTP configuration:
  ```nginx
  server {
      listen 80;
      listen [::]:80;
      
      server_name your-domain.com www.your-domain.com;
      
      root /var/www/healthcare-api;
      index index.html index.htm;
      
      # Security headers
      add_header X-Frame-Options "SAMEORIGIN" always;
      add_header X-XSS-Protection "1; mode=block" always;
      add_header X-Content-Type-Options "nosniff" always;
      
      # Serve static files
      location / {
          try_files $uri $uri/ =404;
      }
      
      # Proxy API requests to Flask backend
      location /api/ {
          proxy_pass http://127.0.0.1:5000;
          proxy_set_header Host $host;
          proxy_set_header X-Real-IP $remote_addr;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto $scheme;
          proxy_connect_timeout 30s;
          proxy_send_timeout 30s;
          proxy_read_timeout 30s;
      }
      
      # Security: Deny access to hidden files
      location ~ /\. {
          deny all;
      }
      
      # Logging for security analysis
      access_log /var/log/nginx/healthcare_access.log;
      error_log /var/log/nginx/healthcare_error.log;
  }
  ```
- [ ] Enable the server block
  ```bash
  sudo ln -s /etc/nginx/sites-available/healthcare-api /etc/nginx/sites-enabled/
  ```
- [ ] Remove default Nginx site
  ```bash
  sudo rm /etc/nginx/sites-enabled/default
  ```
- [ ] Test configuration
  ```bash
  sudo nginx -t
  ```
- [ ] Reload Nginx
  ```bash
  sudo systemctl reload nginx
  ```

## Why Certbot Won't Work for Internal Labs

Let's Encrypt validates domain ownership by either making HTTP requests to your server on port 80 or checking DNS records. Since your lab VMs are on an internal network (192.168.100.x), Let's Encrypt's servers can't reach them to perform validation.

## Better Solutions for Internal SSL Testing

### **Option 1: Self-Signed Certificates (Recommended for your use case)**

Create your own certificates - perfect for security testing since you can control the entire process:

```bash
# Create a Certificate Authority (CA)
sudo mkdir -p /etc/ssl/healthcare-ca
cd /etc/ssl/healthcare-ca

# Generate CA private key
sudo openssl genrsa -out ca-key.pem 4096

# Generate CA certificate
sudo openssl req -new -x509 -days 365 -key ca-key.pem -sha256 -out ca-cert.pem -subj "/C=US/ST=MA/L=Oxford/O=Healthcare Lab/CN=Healthcare Lab CA"

# Generate server private key
sudo openssl genrsa -out server-key.pem 4096

# Generate certificate signing request
sudo openssl req -subj "/C=US/ST=MA/L=Oxford/O=Healthcare Lab/CN=healthcare-api.local" -sha256 -new -key server-key.pem -out server.csr

# Generate server certificate signed by your CA
sudo openssl x509 -req -days 365 -in server.csr -CA ca-cert.pem -CAkey ca-key.pem -out server-cert.pem -extensions v3_req -extfile <(echo -e "subjectAltName=DNS:healthcare-api.local,DNS:www.healthcare-api.local,IP:192.168.100.20")
```

### **Option 2: Use mkcert (Even Easier)**

This tool creates locally-trusted development certificates:

```bash
# Install mkcert
sudo apt install libnss3-tools
curl -JLO "https://dl.filippo.io/mkcert/latest?for=linux/amd64"
chmod +x mkcert-v*-linux-amd64
sudo mv mkcert-v*-linux-amd64 /usr/local/bin/mkcert

# Create local CA
mkcert -install

# Generate certificate for your domain
mkcert healthcare-api.local www.healthcare-api.local 192.168.100.20

# This creates:
# healthcare-api.local+2.pem (certificate)
# healthcare-api.local+2-key.pem (private key)
```

### **Updated Nginx Configuration for Self-Signed SSL**

```nginx
server {
    listen 80;
    server_name healthcare-api.local www.healthcare-api.local 192.168.100.20;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    
    server_name healthcare-api.local www.healthcare-api.local;
    
    # Self-signed SSL certificates
    ssl_certificate /etc/ssl/healthcare-ca/server-cert.pem;
    ssl_certificate_key /etc/ssl/healthcare-ca/server-key.pem;
    
    # SSL settings
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-RSA-AES256-GCM-SHA512:DHE-RSA-AES256-GCM-SHA512:ECDHE-RSA-AES256-GCM-SHA384:DHE-RSA-AES256-GCM-SHA384;
    ssl_prefer_server_ciphers off;
    
    # Security headers
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    
    root /var/www/healthcare-api;
    index index.html index.htm;
    
    # Proxy API requests to Flask
    location /api/ {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }
    
    location / {
        try_files $uri $uri/ =404;
    }
}
```

### **Update Your /etc/hosts File**

On all your VMs (including Kali for testing):

```bash

```
